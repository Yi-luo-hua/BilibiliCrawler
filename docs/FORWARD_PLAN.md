## P3：安装器残留清理（条件触发）

评估已完成，结论与方案对比见 [安装器跨构建覆盖残留评估](INSTALLER_RESIDUE.md)：机制已确认
（卸载清单构建期静态展开、安装段不预清理、update 模式跳过卸载），但至今没有在任何已发布版本的
升级中实际发生——依赖锁从未移除过任何包，PyInstaller 版本未变，当前安装目录与新构建比对残留为 0。

决定采纳方案 A′：用 `NSIS_HOOK_PREINSTALL` 清理 `resources\backend`，但当 `_internal` 下仍存在
`analysis-runs` / `analysis-assets` 时跳过，把机会让给应用首启时的迁移逻辑。不采纳版本化资源目录
（会把小残留放大成整棵旧目录），文档约束只作为落地前的过渡说明。

**触发条件**：任何一次移除 `requirements-desktop.lock` 中的依赖、升级 PyInstaller、或更换 Python
小版本的改动。届时在同一个 PR 内实现 A′ 并补齐三条升级回归：带遗留 run 的 v3.2.0 覆盖升级须跳过
清理且数据完好、v3.3.0+ 覆盖升级须执行清理且残留归零、卸载后用户数据仍保留。

在触发条件出现前不排期，也不作为任何版本的发布阻断项。
