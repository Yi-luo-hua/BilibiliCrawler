### 已关闭：CLIProxyAPI Antigravity HTTP 400

曾作为 P1 记录在本文档，**结论是原假设被证伪，不是修复完成**。该 400 的正文是
`{"error":{"code":400,"status":"FAILED_PRECONDITION","message":"User location is not supported..."}}`
——上游对调用方所在区域的限制，请求在参数被读取之前就已被拒，`temperature` 与 `response_format`
从未被评估。不能靠删字段重发绕过，本仓库无法修复；处理方式在 CLIProxyAPI 侧（为对应认证配置
受支持区域的出口）。

v3.6.0 的 `temperature` 降级**不是**这个任务的产物：它针对 OpenAI 推理模型那类会在 `param` 中
指明字段的拒绝。取证与两类正文的对比见
[Provider 错误与原 run 恢复契约](PROVIDER_RECOVERY.md)。**不要因为再次看到 Antigravity 400 就把
它当作参数兼容问题重新立项。**

## 状态维护规则

- 只有实现、测试和对应验收证据全部完成后，任务才能标记为完成。
- 任务完成后从本文档移除，验收证据归档到对应版本清单；本文档只保留未完成的工作。
- 外部服务偶发成功不能替代可复现证据，历史 provider 的成功也不能证明新 provider 兼容。
- 新发现写入本文档对应任务；版本发布细节写入版本清单，历史版本计划不再追加新工作。
- 对涉及 Key、Cookie、OAuth 或远端错误正文的证据只记录脱敏后的结构化信息。
