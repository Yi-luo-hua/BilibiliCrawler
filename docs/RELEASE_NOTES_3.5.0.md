# BilibiliCrawler v3.5.0

v3.5.0 让分析模块可以由用户自己定义，改进了 provider 失败时的可诊断性，并修复了升级时旧构建文件
残留在安装目录的问题。

## 新功能

- **自定义分析模块**（对应 issue #18）：除 7 个预设模块外，可自行填写标题与提示词新增文本类分析
  模块。最多保存 8 个，单次分析最多启用 3 个；结果进入界面卡片与导出的 Markdown 报告。
- 模块定义随每次分析写入结果快照，因此模块被改名或删除后，历史报告的章节标题仍与运行时一致。
- 提示词作为数据处理：用户文本包裹在显式分隔块内，块外声明它只能描述分析角度，不能改变输出结构、
  字段名与语言。

## 改进

- 分析请求被 provider 以 HTTP 400/422 拒绝时，错误信息会指出对方自报的 `code`、`param` 与
  `status`，不必再去翻服务端日志。这些字段仅在形如裸标识符时输出，否则整体省略，远端措辞不回显。
- 安装器在写入新文件前清理上一版遗留的 sidecar 运行时文件。此前升级不会删除新版本不再包含的旧
  文件，它们会留在 sidecar 的模块搜索路径上。

## 修复

- 未启用任何自定义模块时，分析输出与 v3.4.0 完全一致。
- 自定义模块 id 生成时检查既有 id，无法取得未占用 id 时拒绝创建，不会静默覆盖已有模块。
- 标题与提示词的长度上限按 Unicode 码点计数，与后端一致；emoji 不再被截断成孤立代理项。

## 安装

桌面用户从本 Release 下载 `BilibiliCrawler-Setup-3.5.0-x64.exe` 并核对同页 SHA-256。

Python 用户：

```bash
python -m pip install "bilibili-crawler[mcp]==3.5.0"
```

## 升级说明

从 v3.4.0 及更早版本覆盖升级时，安装器会先清理旧的 sidecar 运行时目录。v3.2.0 及更早版本遗留在该
目录下的运行数据会被保留，交由应用首次启动时的迁移逻辑处理。

清理前会先确认该目录未被占用。若升级时后台仍有分析进程在运行、目录被占用，安装器会跳过清理直接
安装，结果与本次升级前一致，不影响使用。建议升级前先退出应用。
