# 长请求进度契约

D 批，基线 `67b668e`。沿用既有 progress(message, percent) 与桌面 analysis.progress、MCP stage，不新增必填字段或 UI 布局。

- 每次分析使用单调时钟计时；等待消息包含本次分析已用秒数、批次序号/总数（或总结整合）、请求次数和重试次数。
- 开始请求、格式降级及退避重试时立即更新消息；请求仍未返回时约每秒刷新已用时。等待不改变既有百分比，不伪造进度增长。
- 连接超时与读取超时均保持原来的 90 秒，显式传入二元组并在等待消息说明；它们不是整个任务总时限，也不是持续有字节到达时的总读取时限。本批不增加整体 deadline 或调整超时配置入口。
- 重试预算、Retry-After、避免重放读取超时等语义沿用 C；提示包含安全错误码，不包含 provider 正文、地址、模型或凭据。
- 只有调用分析的线程向客户端发出进度；网络线程仅排队状态。取消后立即返回，迟到响应不会发出进度、重试或成功消息；观察者异常也要终止后续重试。
- 总结整合使用同样的等待/重试消息；失败时继续保留已完成批次及 C 的 warning。
- 自定义 processor 的公开 analyze 签名和客户端事件结构保持不变。内部 _call_llm/_call_summary_llm 扩展可选 request_progress，测试替身转发或忽略即可。
- 验证真实慢 HTTP、重试、总结、取消与迟到响应；断言百分比不虚增、超时后能复用原 run。通过既有 SidecarClient 子进程和前端 reducer 验证消息通路。本批不修改 UI 文件，不把协议验证宣称为新的安装包/窗口视觉验收。
